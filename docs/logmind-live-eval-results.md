评估时间：2026-08-25

运行命令：

```powershell
uv run python .\scripts\run_logmind_live_report_eval.py --sample-size 30 --run-live-model
```

评估条件：

- 使用当前配置的 `openai-compatible` 模型。
- 每个样本先经过规则故障分类和 Chroma Top-3 知识检索，再调用模型生成报告。
- 使用 30 条外部人工标注报告评估样本，评估结构、关键证据、引用准确性和事实一致性。

## Bad Case

失败的两个样本是 `report_spring_boot_null_pointer` 和 `report_mysql_sql_syntax_error`。

- 两条样本的故障分类均正确。
- 报告结构、关键证据和事实一致性均通过。
- 失败原因都是未在报告第 7 节列出本次实际检索到的知识标题。

这说明当前主要问题是模型对引用格式的偶发遵循不足，而不是分类、检索或事实依据错误。项目已在报告契约中增加“必须以真实知识标题开头”的约束；后续继续积累此类样本，并在需要时增加引用后处理或结构化输出约束。

## 简历使用边界

这是一组 30 条外部人工标注案例上的真实模型抽样结果，可写为“在 30 条外部标注案例抽样评估中”。它不是线上 SLA，也不等同于大规模公开 benchmark。
